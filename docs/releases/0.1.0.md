# Longreach Qt 0.1.0

Released on 2026-10-23 as a source-only pre-release, tagged `v0.1.0`
at commit `3c5142ae3d3dc8a576dc6081fa0d20497663756f`.

These notes were added retrospectively during preparation of 0.2.0.
They describe the existing 0.1.0 tag; they do not change that tag or
the published release.

## Distribution

The first public pre-release contains the source tree, patches, build
tooling, eight test applications, licences and recorded results.
It builds static Qt 4.8.7, Qt 5.15.19 and Qt 6.8.4 SDKs in Docker for
Windows, Linux and macOS. No prebuilt SDK images accompany 0.1.0.

Build the SDKs locally using [getting started](../getting-started.md).
macOS SDK images are excluded from redistribution because they contain
Apple's SDK; see the [release policy](../releasing.md).

The README and `docs/platforms.md` in tag `v0.1.0` distinguish tested
systems from targets that were built and audited only. Later records in
the current [platform matrix](../platforms.md) are not evidence of a
0.1.0 test run.

## Included features

- One target per Qt generation, operating system and architecture:
  `make qt<N>-<os>-<arch>` builds the SDK; its `-examples` target builds
  the test applications into `artifacts/tests-<image>/`.
- Per-platform patch series retain older operating-system support while
  choosing newer APIs at run time where available.
- Downloads are pinned by SHA256; Git inputs are pinned by commit and
  base images by digest. Mirrors and `make verify-downloads` support
  checking the inputs before a build.
- `make build-all` and `make build-all-examples` prepare the full matrix,
  write logs and a summary, and retry failed targets sequentially.
  A build lock prevents independent build commands from running beside
  an active build. Parallel builds within build-all are configurable.
- Optional Linux integrations load shared libraries at run time: Qt 5
  supports Wayland, multimedia, speech and Bluetooth this way; Qt 6
  amd64 supports Wayland. Missing libraries leave those integrations
  unavailable without preventing the application from starting.
- The same eight test applications cover the public classes shipped by
  all three Qt generations. The runner supports local, Docker, SSH,
  VMware, VirtualBox and selected QEMU systems.
- Qt 6 macOS includes availability guards for APIs newer than 10.13;
  the ARM64 Linux SDKs use sysroots matching their stated floors.

The full [0.1.0 changelog](../../CHANGELOG.md#010---2026-10-23) also
records fixes made since the first tag on 2026-10-15, including download
verification, build caching, strict patch application and build locking.

## Validation and limits

The changelog records successful eight-application runs on Windows 95
OSR2 (Qt 4 i386, QEMU), CentOS 5.11 and Debian 4.0 (Qt 4 amd64),
Mac OS X 10.4.10 Tiger (Qt 4 i386, QEMU), and macOS 10.13.6 (Qt 5/6).
This list is a selection of recorded runs, not a claim that every
architecture and floor was exercised. Consult the result files shipped
in `v0.1.0` for the release's original evidence.

The project is GPL-3.0-or-later. Qt patches, mkspecs and runtime objects
retain Qt's terms; using an LGPL build still requires observing the
licences of the selected modules and dependencies. The default build
profile includes GPL modules. See [licensing](../licensing.md).
